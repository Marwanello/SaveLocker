# v0.5.12

_Released 17 September 2026_

**Conflicts now surface everywhere a save could actually be lost, and Playnite joins Steam and Decky
as a first-class launcher.** This release closes out the "conflict resolution" project end to end —
dashboard, agent UI, Windows tray, Steam Deck Game Mode, Decky, and desktop notifications all show
the same local-vs-cloud picture and resolve conflicts the same way — and adds a companion Playnite
plugin plus agent-side Playnite detection, so a Playnite-launched game gets the same pre-launch
protection Steam already had on Linux.

No database changes.

## Conflicts are framed as "this device" vs. "the cloud," everywhere

Every conflict surface — the dashboard's Backups tab, the agent UI's Conflicts page, the Steam Deck's
own Game Mode screen, and the Decky Quick Access panel — now shows the same two-panel card: **this
device** on one side, **the cloud** on the other, whichever machine actually pushed it named only as
a small caption. Recency ("12m ago") is the headline number on each panel, with a "newer" tag on
whichever side is more recent; the exact timestamp is a hover tooltip. Click a side, then confirm —
no more one-click four-button layouts that make it easy to overwrite the wrong side by accident.

Pressing **Sync now** in the agent UI or the Windows tray's **Sync All** now pauses on each conflict
it finds, one at a time, in a full-screen pop-up — with a **"decide later"** option that always drops
you into the Conflicts page instead of just closing with no trace. Resolving the first conflict in a
queue of several offers to apply the same choice to the rest, so clearing five diverged games no
longer means five separate decisions.

## Steam Deck: a Linux game launch is now blocked on a genuine open conflict

Previously a conflict only mattered once you noticed it in the dashboard. Now, launching a tracked
game on Linux (`savelocker run -- %command%`) checks first: a confirmed, unresolved conflict for that
game blocks the launch outright with a clear reason, instead of letting you play on top of a save that
hasn't actually reconciled yet. This never fires for ordinary lease contention (someone else has the
game open right now), a network hiccup, or any other case — only a real, already-recorded conflict.
Force-pushing or force-pulling past an open conflict now also protects both sides as recoverable
backups and tells the other machine involved to pull, so nothing is silently lost and nobody is left
out of sync without knowing.

## Desktop notifications and the Decky panel

On a plain Linux desktop (including Deck Desktop Mode) with a running notification daemon, an open
conflict now pops up a real desktop notification with a "View conflict" button that opens straight to
the agent UI's Conflicts page — no more discovering a conflict only by tailing a log or happening to
open the UI.

The **Decky plugin**'s Quick Access panel gained its own "Save conflicts" panel and a per-game "if a
save conflict happens, prefer this device" setting, plus a magenta conflict indicator on the library
page's sync chip you can click straight into the resolve popup — all using the same local-vs-cloud
framing as everywhere else.

## Playnite support: agent-side detection, plus a companion plugin

**No plugin required to see your Playnite games.** The agent now reads Playnite's own library
directly (including a portable install) as a fourth game-discovery source alongside Steam, Epic/GOG
via Heroic, and manifest-matched titles — a Playnite-only game now shows up in Add Games with nothing
extra installed.

**A new companion plugin, [SaveLocker-Playnite](https://github.com/Marwanello/SaveLocker-Playnite),**
closes the one thing Windows has never been able to do safely: pull — or block — *before* a game
actually starts, the same guarantee Steam's launch wrapper already gives Linux. It adds "Sync now" /
"Resolve conflict…" menu items and a "Link to SaveLocker" popup inside Playnite itself. Install it
from the new **Playnite plugin** card on the agent UI's Overview page (one click, once the agent is
registered) or manually from the plugin's own releases.

The Windows agent also gained a third self-update slot for this plugin, matching how it already keeps
the Decky plugin current — set `AgentUpdate__PlaynitePlugin__GitHubRepo` if you're hosting your own
fork of the Playnite plugin.

## Smaller fixes and polish

- The console and agent UI now self-host their fonts instead of loading Inter from Google Fonts on
  every page view.
- The Steam Deck's Game Mode "Add Games" list now refreshes every 10 seconds, including on first
  load, so a newly-installed or newly-uninstalled game shows up without restarting the UI.
- `doctor` now names the winning source when a game is discoverable through more than one path (a
  MoonDeck shortcut and a genuine Steam install, for example), instead of silently picking one.
- The conflict card reads file count and newest-change time straight from the archive, so it works
  retroactively on every version ever uploaded — no re-upload needed.

## Before you upgrade

- **Update the agents.** The launch-gate block, the desktop notifications, the Decky panel, and
  Playnite detection are all agent-side — a console-only redeploy gets you the dashboard's new
  Backups/conflict framing, but none of the rest.
- **The Decky plugin and the new Playnite plugin are separate downloads**, same as before — upload
  new builds in Config → Agent updates to offer them to your fleet.
- **No database changes.** Downgrading the container is a clean rollback.
