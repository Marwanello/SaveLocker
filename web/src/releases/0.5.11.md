# v0.5.11

_Released 27 August 2026_

**Uploads got smaller and safer, and the conflict card can finally answer "which side is more
recent?"** A normal push now sends only the save files that actually changed rather than re-zipping
the whole folder every time, the chunked upload path introduced in v0.5.10 now refuses to publish a
truncated archive under a complete archive's content hash, and an open conflict shows file count
plus newest-mtime for both sides so you can see at a glance which one is ahead.

There is one database change (a new per-file baseline table for delta uploads); it is additive and
back-fills itself as agents push, so no manual step is needed.

## Uploads send only the files that actually changed

Cyberpunk 2077 and Fallout: New Vegas keep dozens of multi-megabyte save slots side by side, and a
push previously re-zipped and re-uploaded the whole folder every time even when a single slot had
been touched. Delta upload changes that: the agent diffs a per-file manifest against the server's
stored baseline for its current head and sends only the files that actually differ, plus the
existing baseline references for the ones that didn't.

Measured on an 8-slot 3.2 MB fixture with one file changed: ~400 KB on the wire instead of ~3.2 MB.
A game with three 400 MB slots now deltas instead of re-uploading 1.2 GB on every push.

The server reconstructs the full archive on its end, verifies it hashes to the `ContentHash` the
agent declared, and refuses it otherwise — per-entry hashes only ever proved the pieces. If a delta
ever fails to reconstruct cleanly, the agent automatically retries the same push as a full upload
(the audit log's `upload.delta` entry records "N of M files needed fresh bytes" either way, so a
delta push and a full-fallback push are both visible after the fact).

An agent updating ahead of the server or vice versa is safe: a newer agent talking to an older
server, or an older agent talking to a newer one, falls back to the whole-folder upload path
automatically.

## Chunked upload is now all-or-nothing

The chunked upload protocol shipped in v0.5.10 (`/upload/begin` → `/upload/{id}/chunk` →
`/upload/{id}/complete`) had quietly dropped the all-or-nothing guarantee the single-shot upload
route still has. A chunk that faulted mid-write kept its partial bytes and counted them, so the
client's retry of that same chunk landed behind the server's byte counter and was silently dropped
as a "harmless replay". On the final chunk this could publish a **truncated zip under the content
hash of a complete archive** — which every other machine would then pull believing it was intact.

Fixed. A faulted chunk rolls back to the offset it started at (so a retry is a real write, not a
mis-read replay) and the byte counter only advances once the chunk is durable; `complete` refuses to
publish bytes that aren't a readable archive (422). Nothing that pulled a version between v0.5.10
and v0.5.11 is at risk retroactively — the failure mode required a specific mid-chunk fault
sequence during a push — but the guarantee is back regardless.

The agent's chunk retry also now catches a stalled request instead of letting HttpClient's own
100-second timeout surface as an uncaught cancellation, so a genuinely transient network wobble
retries cleanly. `/api/sync` is single-flight, so the Game Mode "Sync now" button can't report
failure over a sync that was still running and about to succeed.

## The conflict card shows how far ahead each side is

A conflict card previously showed size and upload time per side, but nothing that said which
machine's version has more save data or more recent play. The card now shows **file count** and
**newest file mtime** for both sides, read on demand from each version's archive — no migration, so
it works retroactively on every version ever uploaded.

The mtimes are the ones the agent stamped into the zip at push time, so they reflect when the game
last wrote the save, not when the archive was uploaded — and they're rendered against the reader's
own clock rather than the server's, so two people looking at the same conflict see the same numbers
regardless of what timezone the container runs in.

## Save-path alias, per-game pull-before-launch, and Steam Cloud awareness

Three pieces the Decky plugin needs to make good decisions before launching a game are now on the
agent. All three are optional and default to safe values, so an agent update ahead of a plugin
update changes nothing.

- **A per-game save-path alias** for the "same save on Windows and Linux, different actual
  directories" case. The agent can now record a friendly alias per game so cross-platform saves stay
  clearly one lineage instead of showing as two spellings.
- **A per-game "pull before launch" toggle**, so a game the Decky plugin launches can be told to sync
  down before Steam starts it rather than only after it exits.
- **Steam Cloud awareness at enrollment time**, so a game Steam is already syncing itself can be
  flagged as such and the plugin can default its pre-launch pull off for that one instead of racing
  Steam's own sync.

## Markdown tables now render in the console

The in-app help and release-notes viewer rendered GitHub-flavored markdown tables as raw pipe
characters, worst on the CLI reference page (almost entirely tables). Tables now render correctly,
and a table wider than the pane scrolls sideways rather than being silently clipped.

## Before you upgrade

- **Update the agents.** The chunked upload integrity fix and the per-file delta upload both need
  updated agents to take effect. A console-only redeploy gets you the server side of both, but an
  un-updated agent still uploads whole folders through the single-shot route (which was never at
  risk of the truncation bug in the first place).
- **One additive database change** — a new `SaveVersionFile` table backing per-file delta upload.
  Existing versions get their baseline computed the first time an agent pushes to that game
  afterwards; nothing needs to be re-uploaded by hand. Downgrading the container back to v0.5.10 is
  safe (the older code just ignores the new table).
- **`/api/games` field names are unchanged.** The `id` and `path` fields the Decky plugin reads
  stayed as they were; the three new Cloud/alias/pull-before-launch fields are additive.
