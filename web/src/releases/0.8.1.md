# v0.8.1

_Released 26 October 2026_

**One console entry per game, even when you play it in two emulators — plus two security fixes and
three fixes for things that went wrong on a real Deck.**

One database migration (`AddGameTitles`); it is additive and groups existing games by itself on
first start.

## One entry per game, one save tree per emulator

A game saved with more than one emulator — *Metroid Prime Hunters* in melonDS and RetroArch, the
*Metroid Prime Trilogy* in Dolphin and PrimeHack — used to be two unrelated games. It is now **one
entry** in the console, the agent UI and the Windows tray, with a **tab per emulator** on its page.
Syncing is unchanged: each emulator's save is still its own tree with its own versions and
conflicts, so playing in one never overwrites the other.

- **Grouping is automatic** for emulator games of the same console and region with the same name,
  and a startup pass groups the ones you already have. PC games, Switch titles and games you split
  out by hand are never grouped.
- **Group with…** and **Split out** fix a grouping by hand.
- **Copy this save to another emulator** — melonDS ⇄ RetroArch and Dolphin ⇄ PrimeHack, where the
  file formats really match. The server builds a new version of the other emulator's save, makes it
  that tree's Latest (the old one stays) and queues the pulls. It is refused into an open conflict,
  into a game being played, and between emulators whose formats differ. Offered from the agent's
  game page and from a version row in the console.
- The tray menu lists one entry per game, with a submenu per emulator for Sync, Push now and Pull
  latest.

## Security

- **Autorun folders can never be save folders.** One machine's key could name a Startup folder as a
  game's save folder for every agent in the fleet, and the restore would write files into it. The
  Windows Start Menu (both Startup folders), `~/.ssh` and the Linux autostart, systemd and KDE login
  folders are now refused as a save folder, inside one, or holding one — on the agent and on the
  server, which also refuses an agent-supplied literal save folder.
- **The local API token only goes to your own account.** The agent's page carries its API token;
  another account on the same machine could fetch it over loopback. It is now served only to a
  process of the same OS account.
- The audit log's CSV export neutralises cells that a spreadsheet would run as formulas.
- The server image pins Node 22.23.4 and refreshes `ca-certificates`, for the eMudhra distrust.

## Fixes

- **A Deck that lost power right after a Linux self-update came back with an empty agent.** The
  update now flushes every file to disk before it commits, an interrupted install resumes, and the
  service starts through a preflight that restores the previous version if the binary is empty or
  will not start.
- **"TLS identity has CHANGED" no longer fires on every certificate renewal behind Cloudflare.** A
  new key that validates for the host and is publicly logged re-pins quietly; a private
  certificate's new key, an unlogged certificate on a public server, or a failing chain still warns,
  now with the reason. `savelocker trust` and `doctor` say which rule applies.
- **A tracked PC game no longer hides emulator saves.** Add games treated every emulator save as
  "already added" on a Deck tracking PC games, and Steam ROM Manager shortcuts were recorded on the
  PC game instead of the emulator's.

## Before you upgrade

- **Back up `/data`.** The migration is additive, but the server takes a *Before upgrade* snapshot
  on its own and a downgrade is not a clean rollback — restore the snapshot instead.
- **Update every agent** to see the tabs and Copy on a machine; an older agent keeps syncing the
  games it has.
