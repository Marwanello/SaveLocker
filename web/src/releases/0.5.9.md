# v0.5.9

_Released 16 August 2026_

**Console-only.** Nothing here touches an agent, so there is no fleet to update — redeploying the
container is the whole rollout. No database changes: everything new is stored in the existing
settings key/value table.

This release cleans up four things in the dashboard that had grown rough around the edges: two
routine auto-update confirmations were reading as alarms, the audit log couldn't say what actually
changed for three kinds of events, the Agent Updates card had become the busiest thing on the page,
and "how often should the server check GitHub" was a bare number instead of a schedule.

## Routine updates no longer look like problems

An agent applying a downloaded update, or the Decky plugin updating itself, is the auto-update
feature working exactly as intended — not something that needed your attention. Both used to show up
identically to a real fault: a red "N problems" badge on the Machines table, and a ⚠ in the header
with no way to tell what it actually was.

They're now their own category. The badge is blue instead of red, reads "N updates" instead of "N
problems", and hovering it shows what happened. The header's fleet-wide indicator does the same —
you'll only ever see the alarming ⚠ styling for something that's actually alarming.

## The Audit Log can now say what changed, and export to CSV

Three kinds of events used to write an audit entry that didn't say much:

- **Package updates** — installing an agent or Decky plugin package, whether uploaded by hand, fetched
  from GitHub on demand, or picked up by the background poller — wrote nothing to the audit log at
  all. All three now do, and the poller only speaks up when it actually changes something.
- **Conflict resolution** used to record a bare pair of version IDs. It now names which machine's
  version was kept and which was discarded (or both, when you chose "keep both") — the detail you
  actually need if the wrong side ever gets picked and you have to find out why.
- **Exclude-pattern changes** used to record only a count ("3 pattern(s)"), never which pattern was
  added or removed. It now diffs the old list against the new and writes exactly that.

The Audit Log page also has an **Export CSV** button, next to Refresh. It exports whatever page of
events is currently loaded.

## Agent Updates: one status card, one Edit button

Managing three packages — the Windows installer, the Linux tarball, and the Decky plugin — used to
mean three full sets of upload/fetch/delete controls sitting directly on the Config page at all
times, whether or not anything needed doing.

The card is now a glance: version, source (manual upload or GitHub fetch), and date for each
package. Everything else lives behind a single **Edit** button:

- **Fetch latest for all packages** — all three pre-checked, uncheck any you don't want touched, one
  click fetches the rest from GitHub.
- **Hash verification**, per package, on demand — compares the hosted file's SHA-256 against the
  `SHA256SUMS*.txt` published on that package's GitHub release, so you can confirm what the server is
  handing out actually matches what GitHub built. (The Decky plugin's repo doesn't publish one of
  these yet, so it reports "unknown" rather than a false pass or fail.)
- The original per-package upload, individual GitHub fetch, and delete controls are all still there,
  just inside the modal instead of on the card.

## A real schedule for the automatic GitHub check

"Check GitHub for a newer package every N hours" is still there, but it's no longer the only option.
The Edit modal's schedule section now supports:

- **Disabled**
- **Every N hours** (unchanged — same behavior as before, including checking immediately when you
  turn it on or change the interval)
- **Weekly**, on a day of the week and time of day
- **Monthly**, on a day of the month and time of day — day 31 lands on the last real day of a shorter
  month rather than being skipped

Weekly and monthly times are your **server's** local clock, not your browser's, which the modal says
outright so it's never ambiguous when the server and your browser disagree. Switching to a weekly or
monthly schedule schedules its next occurrence — it does not fire an immediate check just because you
saved, the way changing the hourly interval always has.

The card shows the current schedule as a sentence — "Checks GitHub every Wednesday at 14:30 (server
time). Next check 8/19/2026, 2:30:00 PM." — instead of an always-visible input field.

## Before you upgrade

- **Console only.** Redeploy the container (`docker compose pull && docker compose up -d`); there is
  nothing for any agent to install.
- **No database changes.** Downgrading the container is a clean rollback.
- If anything outside the dashboard calls `POST /api/settings/agent-update-auto-fetch` directly, its
  request body shape changed — from `{ hours }` to the full schedule
  (`{ mode, hours, dayOfWeek, dayOfMonth, timeOfDay }`). Nothing in this repo does that today; this
  only matters for a script or integration you may have written against the old endpoint.
