# v0.5.7

_Released 15 August 2026_

**The Decky plugin now keeps itself up to date, and the console stops accepting a SteamGridDB key
that does not work.** The second one is a quiet data-loss risk worth knowing about: since some point
before this release, saving a mistyped key in **Configuration** would report success and replace the
working key you had.

No database changes. No save data is touched by upgrading.

## The console accepted API keys that were not valid

If you pasted a SteamGridDB key with a typo in it, the console said *"API key verified with
SteamGridDB"*, stored it, and threw away the key that was working. The only way back was to find the
original again.

This is fixed. A key is now checked against SteamGridDB before anything is stored, and a bad one is
refused with the reason — *invalid key format*, *invalid API key*, or *authentication required* — and
**your existing key is left exactly where it was**.

The cause is worth a sentence, because it explains why it came back after being fixed once before.
SteamGridDB sits behind a CDN that had cached a successful response for the address the console used
to check keys. Those checks were being answered from the cache, so SteamGridDB itself never saw the
key at all and every key looked valid. The check now uses an address nothing can have cached.

**If artwork stopped appearing for new games, this may be why.** Re-paste your key in
**Configuration → SteamGridDB**; if it is genuinely wrong you will now be told so instead of it
silently taking effect.

## The Decky plugin updates itself

If you use the optional [Decky Loader](https://decky.xyz) plugin on a Steam Deck, your SaveLocker
agent now updates it for you, on the same schedule it uses for its own updates. Decky reloads the
plugin within about a second — no sudo, no Steam restart, nothing to click.

This exists because the alternative was bad. Decky holds exactly **one** custom store URL, and
setting it *replaces* the official store — so subscribing to SaveLocker's plugin updates meant giving
up every other plugin's. In practice nobody does that, which meant nobody was ever told a plugin
update existed.

**To turn it on, upload the plugin's release zip in Configuration → Agent updates → Decky plugin.**
That card now has three rows: Windows, Linux, and the plugin. Nothing is offered to any Deck until
that row is filled.

Two things it deliberately will not do:

- **It cannot do the first install.** Creating the plugin's folder needs root. That stays a one-time
  paste of the plugin URL into Decky's *Install Plugin from URL*.
- **It will not half-apply an update.** Decky keeps parts of a plugin's folder owned by root, so the
  agent checks every file it would write *before* writing any of them, and refuses the whole update
  rather than leaving a plugin half on one version and half on another. If that happens, `savelocker
  doctor` says so and a single manual reinstall fixes it for good.

If your plugin was installed before it shipped its reload flag, it cannot update itself — that flag
lives in the one file the agent is not allowed to rewrite. Reinstall it once from the URL and it will
keep up from then on.

`savelocker plugin-update` does it immediately if you would rather not wait, and `--check` reports
without installing. Turning off `AutoUpdate` stops the plugin being replaced too — you are still told
when it is behind.

## The agent UI now mentions the plugin — and whether you have it

The Overview tab has a **Decky plugin** card under the launch-options card. It is collapsed to a
single line by default and expands if you want the detail, and it reads your machine's actual state:
it shows the installed version once you have it, and only offers install instructions when you do
not.

`savelocker doctor` reports the same thing: whether Decky is present, which plugin version is
installed, and whether a newer one is waiting.

There is also a new help article — **The Decky plugin (Steam Deck)** under Configuration — covering
what it does, how to install it, and why it is not in the Decky store.

## What has and has not been tested

Being straight about this, because it is a Deck feature and Decks are hard to test on.

The plugin update path is fully covered by the automated Linux suite against a stand-in plugin
folder, and the file-replacement mechanism it relies on was confirmed by hand on a real Deck while
the plugin was being built. **The agent performing a plugin update by itself, end to end, has not yet
been watched on hardware.** If it fails it fails safely — the old plugin keeps working, the failure
is reported to the console, and reinstalling from the URL always works.

The same is true of the agent updating *itself* on a Deck: everything it needs has been in place
since v0.5.5 and each piece is proven, but the unattended run has not been observed. v0.5.7 is a good
one to watch.

## Before you upgrade

- **Update the agents.** The console half of this release is the SteamGridDB fix and the notes you
  are reading.
- **Decks running v0.5.5 or later update themselves** once the Linux tarball is uploaded in
  **Configuration → Agent updates**. Older Decks need one hand-run of `install.sh`.
- Windows agents update themselves once the installer is uploaded in the same place. Nothing is
  offered to either fleet until those rows are filled.
- **No database changes.** Downgrading the container is a clean rollback.
