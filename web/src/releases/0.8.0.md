# v0.8.0

_Released 21 October 2026_

**SaveLocker now syncs emulator saves.** A RetroArch `.srm`, a PCSX2 memory card, a Dolphin save, a
Ryujinx title folder or an Xbox 360 profile is no longer invisible to SaveLocker: it is found on its
own, listed in **Add games** with its emulator and console, and synced between your PC and your Deck
like any other game — the same save on both, same conflicts, same version history. Save states sync
too, as a second folder of the same game, and a game you have only ever played from a state is still
a game.

**Emulator saves are an EmuDeck feature, and only EmuDeck has been tested.** Detection is built for
EmuDeck on Linux (including SteamOS) and Windows; a hand-rolled emulator setup is not supported, and
SaveLocker may not find its saves.

Eleven database migrations — see *Before you upgrade*.

## Emulator saves

- **Built in:** RetroArch (saves and save states), melonDS, ScummVM, Supermodel and Model 2, PCSX2,
  DuckStation, Dolphin and PrimeHack, PPSSPP, RPCS3, Vita3K, shadPS4, Cemu, Azahar (and Citra's
  folders), Xenia — and the Switch emulators: Eden, Citron, Yuzu, Suyu, Sudachi and Ryujinx.
- **Add games** lists each save with its emulator and console, with *Emulators* and *Console*
  filters and a small icon per platform. A game listed once is one game, however many emulators the
  fleet runs it in.
- **Save states are a second folder of the same game**, so a `.srm` and its `.state` files travel
  together. A state is still tied to the core that wrote it — syncing does not make a state portable
  between different core builds or emulators.
- **Names come from real title data** (No-Intro, Redump and blawar's eShop titles), not from folder
  names: *Prince of Persia - Warrior Within*, not "Prince of Persia". A game's region, IDs, console
  and languages are kept as its release details, behind the region chip on its page; two regions of
  one disc are two games that never overwrite each other.
- **Each machine records how it found a game** — "Emulator › RetroArch", "Steam › Installed game",
  "Playnite" — shown on the game page, so a game found on three machines says where from.
- **Awkward cases are handled, not guessed at:** a memory card shared by every game is a greyed-out
  row with what to change, EmuDeck's preinstalled NVRAM seeds are never mistaken for saves, a game
  whose ROM is known but whose save does not exist yet is listed as *No save here yet*, and a game
  played only from states is listed as *Save states only so far*.
- **Steam ROM Manager shortcuts are the emulator's game**, not a second copy of it: on a Deck,
  Forza Horizon is one entry, and launching it from Steam still syncs it.

## Switch: one game per title

- **One game per title across every Switch emulator** — Yuzu, Eden, Citron, Suyu, Sudachi and
  Ryujinx are not six games. A game you play in two of them on one machine gets a **copy** card in
  the agent's Emulator settings: copy it over once, keep the copies in sync (the one played last
  wins, and it asks when both changed), or make one the copy that syncs.
- **On this device, you play it in** picks the emulator that should hold the save, moves it there,
  and shows each install's game version — so a save from a newer game version is not pulled into an
  older one and called "damaged".
- **One Switch user on every device** (Settings → One Switch user): EmuDeck's Yuzu-based emulators
  save under a user ID, and a game like Animal Crossing ties residents to it. SaveLocker can adopt
  one user ID everywhere, back up the saves it moves, and put a device's own user back.

## Xbox 360: profile and DLC

Xenia keeps its save in the emulator's profile, not per game. SaveLocker now checks the profile at
launch and keeps only the part belonging to the game being played, so a profile change from one game
no longer travels with another. The game's **DLC and title updates** are listed per version and per
machine in the agent's and console's Emulator settings pages: a pull can be held while a machine is
missing the DLC the save needs, and packs can be sent through the server (up to 8 GB by default; a
sender offers them automatically). A game started outside SaveLocker's launch path — straight from
EmulationStation, say — gets no profile check or held pull.

## Linking saves by hand, and merging games

- Every emulator row in **Add games** says which server game the save joins, with **Change**:
  automatic, *Keep it as its own game*, or a specific other game keeping the same files. Emulator
  saves from different emulators are never one game.
- When two machines name the files differently (a different dump, a different region suffix), the
  game can be linked with a **file-by-file name list** that grows by itself as the machines sync.
- Two games that turned out to be one — an older split — can be **merged** from the console: a
  preview of what will move, then one typed name to confirm. The merged versions stay as read-only
  history.

## Join links replace the enrollment file

The JSON enrollment file is gone. The console's **Enroll a machine** now mints a short single-use
code (shown as a link and a QR): opening it shows a pairing page with the Windows installer and the
Linux one-liner, and an agent that is already installed takes the same link in its **Join a server**
card. On Linux, the installed menu entry also registers a `savelocker://` link, and releases carry a
double-clickable installer that installs, enrolls and opens the Join card. Codes are throttled —
15 unknown-code attempts per client per 15 minutes — and a code that expires is simply replaced.

**An agent or installer older than v0.8.0 cannot enroll with a link** — update it first, or keep
using `savelocker register` with an API key.

## Save safety

- **An emptied save folder is held, not pushed.** If a game's folder on this machine becomes empty
  while the server's latest version has files, SaveLocker stops and asks: the agent UI, `doctor`, a
  notification, the console's bell and the CLI show *Delete everywhere* or *Restore here*. The
  server refuses an unforced empty archive over a version that has files, so one broken machine can
  no longer wipe the fleet.
- **A pull keeps this machine's excluded files.** Exclude patterns used to protect files from being
  uploaded and then delete them on the next pull; a pull now neither writes nor deletes anything
  that matches an exclude.

## Smaller, but worth knowing

- **The manifest refreshes on a schedule.** Save-detection data was downloaded once and then served
  forever. It now refreshes in the background (default: every 3 days), the window is set in
  Configuration → Defaults & maintenance, and **Refresh now** asks every machine at its next poll.
  Manifest paths were also hardened: a template that resolves outside where the manifest says it
  lives — through `..` or through a symlink — is refused.
- **Artwork: choose which SteamGridDB entry a game uses**, with search and *Use automatic match*.
  The agent now keeps covers and icons on disk, so art still shows with the server unreachable.
- **Save file trees.** A version in the console opens on the files it changed, and the agent's game
  page has *Save files on this PC* — every file Marked in sync, will push or will pull.
- **Notices that act.** A Windows toast for a failed push has **Retry now**; an available update
  has **Install now**; both work even if the tray was closed.
- **No more silent duplicate shortcuts.** Add games warns when Steam holds two shortcuts with one
  name and says which AppID will be tracked; Game Mode shows the same warning.
- **Registration needs the admin password by default.** Once a password is set, a *new* machine name
  must present it. A scripted `savelocker register` without `--admin-password` now gets a 401 —
  add the password, or an enrollment link.
- **The Linux agent's state files are owner-only** (0700/0600), including `config.json`, `api-token`
  and `agent.log` — and files older builds left readable are tightened.
- Console smaller things: the games list sorts and groups, a game page can be searched for and its
  save-folder sections collapsed, signed-in browsers are listable and revocable one by one, a
  deleted game's cached art goes with it, and sign-in lockouts appear in the bell.
- The agent UI can be driven by a controller, with a hint bar that follows the last input used.

## Before you upgrade

- **Back up `/data`.** Eleven migrations run on first start; the server takes a *Before upgrade*
  snapshot on its own, but a downgrade after that is not a clean rollback — restore the snapshot
  instead.
- **Update every agent.** Emulator detection is agent-side: an older agent keeps syncing the games
  it already has and cannot add emulator saves. The console flags machines behind this version.
- **Enrollment files no longer work.** Old agents and old installers cannot enroll until updated;
  `savelocker register` still works from an old agent.
- **Scripts that register machines** must now pass the admin password (or use a join link) when one
  is set.
- **Save states are best-effort across different core builds.** They are synced because losing them
  is worse than a state that fails to load; a state written by one core version may not load in
  another.
- **Emulator saves need EmuDeck on Linux or Windows.** Only EmuDeck installs were tested, and
  hand-rolled emulator setups are not supported.
- **Model 2 is the one emulator with no real-game check yet** — it ships, but nobody has played a
  Model 2 game against it. The rest of the list above was exercised with real games on real
  hardware, through EmuDeck.
