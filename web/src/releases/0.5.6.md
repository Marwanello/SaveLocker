# v0.5.6

_Released 15 August 2026_

**A Steam Deck game could be tracked, mapped, and set up correctly — and still never have its saves
backed up.** This release fixes that, and it is the reason to take it. If you sync any game on a
Deck, read the next section: you may have been affected without anything telling you.

Also in this release: SaveLocker can now tell you whether a game's Steam **launch options** were ever
set, and there is an optional Decky plugin that sets them for you.

No database changes. No save data is touched by upgrading.

## Check whether this affected you

On the Deck, run:

```
savelocker doctor
```

Look at the **Tracked games** section. Before this release, a game whose `appid` read
`(none — the launch wrapper cannot match this game)` **was not syncing at all**, no matter how
correct everything else looked. There was no error, no console warning, and no failed sync — the
game simply ran and nothing was saved. The only trace was one line in the agent log:

```
[run] no tracked game matches this launch — running without sync.
```

After upgrading, those games recover their AppID automatically from their own save folder and start
syncing on the next launch. **Their existing saves are still on the Deck** — nothing was deleted,
they were only never uploaded — so the first sync after this release will push whatever is there.

If a game's most recent progress lives on the Deck and an older copy is on the server, launch it once
on the Deck and let it push before playing that game anywhere else.

## Why it happened

A game running under Proton is identified by its Steam AppID, and the launch wrapper uses that to
work out which tracked game is starting. Games added by hand — or by an older version of the
agent — could end up with no AppID recorded. The wrapper then matched nothing and ran the game
without syncing.

A Proton prefix directory is *named* for the AppID that launches into it, so a save folder mapped
inside one already carried the answer. The agent now reads it from there, and writes it down so the
game list and the console show it too.

## Launch options: SaveLocker can now tell when they are missing

Adding `savelocker run -- %command%` to a game's **Launch Options** is the last manual step of Deck
setup, and the easiest to forget. Until now nothing noticed when it was skipped — the game just never
synced, with nothing connecting that to a text field you never opened.

- `savelocker doctor` now reports each game's launch options as **set** or **unknown**, and prints
  the exact string to paste.
- `savelocker launch-options` prints that string on its own; `--list` shows every game, and
  `--check` exits non-zero if any is unconfirmed, for scripting.

"Unknown" is not a fault. SaveLocker cannot read Steam's launch options itself — Steam rewrites its
own configuration when it exits, so nothing outside Steam can reliably read or change it — so unknown
simply means nothing has confirmed them.

## Optional: the Decky plugin

For Decks running [Decky Loader](https://decky.xyz), there is now a SaveLocker plugin that sets
launch options for every enrolled game from the Quick Access menu, so you never paste that command
again.

It runs inside Steam, which is the only place that can change launch options reliably. It **merges**
rather than overwrites: a game already running `mangohud`, setting environment variables, or passing
its own arguments keeps all of it. It also repairs the most common mistake — a bare `savelocker`
instead of the full path, which silently stops a game launching in Game Mode because
`~/.local/bin` is not on `PATH` there.

Writing is **off** until you turn it on, and it shows what it read and what it would change first.

The plugin is an accelerator, not a requirement. Nothing about setting launch options by hand has
changed, and a Deck without Decky Loader loses nothing.

## Before you upgrade

- **Update the agents.** This release's fixes are all agent-side; the console change is only the
  notes you are reading.
- **Decks running v0.5.5 update themselves** once the Linux tarball is uploaded in
  **Config → Agent updates**. Older Decks need one hand-run of `install.sh`.
- Windows agents update themselves once the installer is uploaded in the same place. Nothing is
  offered to either fleet until those rows are filled.
- **No database changes.** Downgrading the container is a clean rollback.
