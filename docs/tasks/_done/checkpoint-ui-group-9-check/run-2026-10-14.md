## Findings

1. **F1 — "Backups to keep" cannot be set back to 7 (P3, UI).** The select (`ConfigView.tsx:546`)
   offers `[2,4,8,12,26,52] + current`; after choosing 2, **7 disappears** and checklist 2.5's "set
   keep back to 7" is impossible from the UI (an API call restored it). Fix: always include the
   default, or make it a number field.
2. **F2 — checklist 3.1's premise is stale (not a product bug).** A console-side resolve queues a
   *guarded* pull (PR #64-67 deliberately kept server-queued pulls guarded); a machine whose save was
   never synced refuses it (`BLOCKED pull … Push first`) and re-conflicts on its next save. "Wait
   until Conflict Game shows a new Latest" therefore cannot succeed in this setup; the restore/undo
   path itself is unaffected. Rig unblocked with an admin resolve + `savelocker pull all --force`.
3. **F3 — checklist literals.** The live DB in the container is `/data/localgamesync.db` (3c's
   `docker cp …/savelocker.db` fails as written; the name inside backup zips is still
   `savelocker.db`). "What's new" renders a typographic apostrophe.
4. **F4 — enrollment on a localhost console (checklist gap).** "Create enrollment file" is disabled
   until the optional *Server URL the agent should use* is filled (the LAN-URL guard from the
   easy-wins work, working as designed). The checklist should say so; filling the field enabled the
   mint in this run.
5. **F5 — revoking removes the row (behavior drift).** After Revoke → confirm, the enrollment row is
   gone from the table (`/api/admin/enrollments` returns `[]`); the checklist expects it to stay with
   a grey **Expired** chip. Rejection itself works. Either the checklist or the UI should change.
6. **F6 — `-test` builds classify as releases.** `BuildInfo.isRelease` (`BuildInfo.cs:54`) treats any
   version without `+` as a release, so `0.7.1-test` shows **no "Dev build" chip** (4.2), **no dev
   banner** in What's new, and **no "Running" chip** against v0.7.1 in Release history (7.3). Real
   tag builds are unaffected. Options: stamp testenv/CI dev builds with `+<n>.<sha>`, or treat
   `-test`/`-ci` suffixes as non-release. Maintainer call.
7. **F7 — Help article renamed; "snapshot" moved (checklist stale).** The backups article is now
   **"Backups and restoring"** (18 articles, not 17) and contains no "snapshot"; searching
   `snapshot` finds *Understanding sync conflicts* and *Emulator backup best practices*.
8. **F8 — "Fetch from GitHub" defaults to the upstream repo.** `AgentInstallerService.cs:84` defaults
   `AgentUpdate:GitHubRepo` to `SkorcherX/SaveLocker`, so on this fork's rig the fetch pulled
   **v0.5.9** (upstream's latest) and hosted it in the win-x64 slot, while the console runs
   0.7.1-test and the fork's own latest is newer. If fork deployments should fetch
   `Marwanello/SaveLocker`, set that config there or change the default.
