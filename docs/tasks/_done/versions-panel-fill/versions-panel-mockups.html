Filling the space beside a short Versions list

Today the Versions card sits alone in a 1.45 : 1 left column next to Save folders, Rules and Exclude patterns. A game with one or two versions leaves a tall empty well under it. Three ways out — each drawn with a 1-version game and a 14-version game. All three are live layouts: resize the window and they reflow.

Idea A

Balanced columns — cards flow to the shorter side

  • Versions stays first on the left; every card after it is placed in whichever column is shorter at that moment.
  • With one version, Rules and Exclude patterns slide in under Versions; the right column keeps Save folders.
  • Re-balanced by a ResizeObserver whenever a card grows (a row expands, Save folders collapses, a version arrives).
  • Smallest change to the page: the same cards, the same order on narrow screens (one column).

Idea B

Versions stretches — spare height becomes save activity

  • Versions is as tall as the right column, always; the two columns end on one line.
  • Short list: the leftover height turns into a per-machine timeline of saves and a retention meter (1 of 10 kept).
  • Long list: the table scrolls inside the card (sticky header), and the activity folds into a one-line strip.
  • Nothing moves between columns, so the page never jumps when a version arrives.

Idea C

Size by content — tiles when few, table when many

  • Up to three versions: Versions spans the page as version tiles, one per save, with the spare tile slots shown empty.
  • The other cards reflow into an auto-fit grid underneath — as many columns as the width allows.
  • Four or more: the familiar table, capped at eight rows with “Show all 14”, the same reflowing grid below.
  • Biggest change, and the most even page at every count.
